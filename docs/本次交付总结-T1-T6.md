操作口诀：
- 先找配置，再找组件，再找数据源
- 先改最小文件，不要整页重写
- 只改视觉时尽量不动数据结构和路由

## 七、常规修改 SOP

### 改组件样式
1. 先定位组件文件，例如卡片、导航、横幅、评论、搜索
2. 只改对应组件或其样式，不要先碰全局配置
3. 保存后跑 `pnpm build`
4. 若涉及页面可见性，再跑 `scripts/smoke-check.mjs`
5. 通过后提交并推送 `main`

### 改页面结构
1. 先看 `src/pages/` 里对应路由文件
2. 再看它引用的布局组件与 widget
3. 维持现有 DOM 层级，不要为了视觉重排把数据结构打散
4. 改完跑 build，确认首页和目标页都能渲染

### 改数据内容
1. 内容型改动优先改 `src/content/posts/` 或 `src/data/*.json`
2. 文章用 Markdown frontmatter，数据页保持 `{ items: [...] }` 结构
3. 改完确认后台字段仍和 `public/admin/config.yml` 对齐
4. 再跑 build 和路由冒烟

### 发布
1. 确认工作区干净
2. `git add`、`git commit`
3. 推 `main`
4. Cloudflare Pages Git 集成会自动部署
5. 用线上首页和关键路由复核

### 必带守卫
1. `pnpm build` 前先设 `CODEBUDDY_SAFE_DELETE_ENABLED=0`
2. 本地预览优先用 8080 或 3001，避开 4321
3. 不要提交 `.codebuddy/`
4. 不要把部署密钥写进仓库

## 九、踩坑清单

- Typecho / 旧站切换到 Pages 时，旧 Worker route 可能抢流量
- 自定义域可能仍指向旧构建，需要检查 Pages custom domains 和 DNS
- `pnpm build` 前若未设 `CODEBUDDY_SAFE_DELETE_ENABLED=0`，清理 `dist/.prerender` 可能触发安全删除守卫
- `pnpm dev` 避免使用 4321，Windows Hyper-V 保留段会冲突
- Giscus 需要：
  - 安装 GitHub App
  - 正确的 node_id 版 `repoId/categoryId`
  - 仓库权限和分支策略正常
- Decap CMS 需要：
  - `OAUTH_CLIENT_ID`
  - `OAUTH_CLIENT_SECRET`
  - 正确的 GitHub OAuth 回调
- `.codex/` 是本地运行痕迹，容易被残留进工作区，必须加入 `.gitignore`
- 残留 `astro dev --port 3001` 可能锁住 `.codex` 日志文件
